# Project: Gender in the IOM World Migration Reports (2000 to 2026)

Undergraduate honours project (IIIT Hyderabad), possible basis for a thesis.
The examiner is a humanities and social sciences professor, so every method
must be explainable, auditable and reproducible.

## Research question

How did the IOM World Migration Reports (2000 to 2026) represent the
feminization of migration, and to what extent were their claims consistent
with the statistics they published?

1. When, if at all, did the reports shift from asserting to contesting the
   feminization thesis? (Analysis 1: claims vs numbers)
2. How have the reports framed women migrants, and how has this framing
   changed over time? (Analysis 2: victim or agent)

Method: computational grounded theory (Nelson 2020). Computation detects
patterns, close reading interprets them, systematic coding confirms them.

## Corpus

13 editions: 2000, 2003, 2005, 2008, 2010, 2011, 2013, 2015, 2018, 2020,
2022, 2024, 2026. PDFs in `data/raw/` named `wmr_<year>.pdf`.

Main dataset: `data/processed/sentences.parquet`, one row per sentence:
edition, chapter_no, chapter_title, chapter_type, author, page, para_id,
sent_id, text, is_heading, in_references, n_words.

For analysis, normally filter to prose: `~is_heading & ~in_references`.

## Folder rules

- `data/raw/`: never modify.
- `data/interim/`, `data/processed/`: generated by scripts, safe to rebuild.
- `data/coding/`: hand-coded by the researcher. Scripts may READ these files
  but must NEVER overwrite or edit them. Write new exports to a new filename.
- `config/lexicons/`: all word lists live here as plain text or CSV, never
  hard-coded inside scripts.
- `src/corpus/` Phase 1, `src/claims/` Phase 2, `src/framing/` Phase 3,
  `src/viz/` all plotting.
- `notebooks/`: exploration only. Anything used for results goes in `src/`.
- `prompts/ai_summaries/`: every AI summary prompt and output, dated.
- `docs/decisions_log.md`: record every methodological change.

## Conventions

- Python 3, pandas, spaCy, PyMuPDF. Parquet for data, CSV for anything the
  researcher opens in a spreadsheet.
- Run scripts as modules from the project root: `python -m src.claims.numeric_claims`.
- Every script accepts optional edition years so it can be tested on one
  edition first.
- Fix random seeds (42) for any sampling or model training.
- Plots: matplotlib or seaborn, saved as PNG (300 dpi) and PDF in
  `outputs/figures/`, readable in black and white.
- Keep `sent_id` on every derived row so results trace back to the source.
- Do not use em-dashes in any written output (reports, figures, docs).

## Phase 2 plan (next)

1. `gender_filter.py`: flag sentences matching `config/lexicons/gender_terms.txt`.
2. `numeric_claims.py`: find sentences with a figure (per cent, %, "almost
   half", counts) referring to women or female migrants. Use spaCy to check
   the number refers to women. Output CSV with edition, sent_id, value,
   reference year, scope (global / workers / regional / country), text.
   The researcher verifies every row by hand.
3. `trend_claims.py`: keyword patterns (feminiz*, feminis*, "increasing share
   of women", etc.) plus semantic search with sentence-transformers against
   seed sentences in `config/lexicons/trend_seeds.txt`. Output candidates
   with similarity scores for manual review.
4. `export_for_coding.py`: spreadsheet for coding trend claims as asserted /
   hedged / disputed / reported_debate, with an empty column for a second coder.
5. `kappa.py`: Cohen's kappa between coders, plus a confusion table.
6. `src/viz/claims_timeline.py`: editions on x-axis, printed female-share
   figures as points by scope, trend claims marked by category.
